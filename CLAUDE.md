# Homegrown contributor guide

This document describes the checked-in application. User-facing usage is in
`README.md`; build and packaging instructions are in `docs/build.md`.

## Commands

```bash
# Development from the repository root
npm run dev

# All automated tests (Studio tests followed by backend unit tests; no builds)
npm run test

# Frontend lint and production build (production build is separate from tests)
cd apps/studio && npm run lint && npm run build
cd ../..

# Regenerate checked-in loading skeletons after changing their fixtures or layout
# (start Vite on 127.0.0.1:5173 first)
cd apps/studio && npm run bones:build

# Backend syntax check
python -m compileall -q services/voice-api/homegrown_api
```

`npm run build` is a ten-stage packaging pipeline with a numbered overview
(without a `PLAN` heading); each row shows a measured baseline ETA (for example
`(17:42m)` for backend freezing) until the current run replaces it with its
actual duration. A stage shows `(measuring)` only when no baseline exists.
Interactive terminals get a live
ANSI progress bar; CI and redirected output get line-oriented progress
without escape sequences. Detailed child output is written to
`.tmp/build-logs/build-<timestamp>.log`, including stage start/completion,
cumulative elapsed times, and a final machine-readable timing summary. Failures
show only the failed stage and a bounded tail. The build still restores `apps/studio/.env.local`
on success, failure, or interruption and produces the same self-extracting
`dist/Homegrown-<version>.exe` artifact. Its concise success summary shows the
duration, size, and absolute installer path; in interactive terminals the path
links to the containing directory, while redirected output stays plain text.

`npm run dev` starts Vite on `:5173` first, then FastAPI on `127.0.0.1:8000`,
via `concurrently` from the root `package.json`. Vite proxies `/api`, `/audio`,
and `/refs`. The finished-product path is `npm run build` followed by the generated
`Homegrown-<version>.exe`. Both root commands are thin wrappers over
`scripts/dev.mjs` and `scripts/build.mjs`.

## Architecture

- `services/voice-api/homegrown_api/app.py` composes the API routers and static Studio host.
  `generation/model.py` owns model state, `generation/worker.py` owns the queue, and
  `persistence/stores.py` owns JSON stores. See `docs/architecture.md` for boundaries.
- `apps/studio/src/app/StudioShell.tsx` composes voices, generation, and
  queue activity. `SettingsModal.tsx` owns the header Settings dialog:
  `ThemeSwitch.tsx` persists the System or named theme choice, while the
  mascot-visibility switch persists only a browser-local preference.
  `HistoryList.tsx` renders completed and live voiceovers.
- `features/startup/RuntimeStatus.tsx` is the mounted model/compute status
  surface. It appears above Voices below 760px, beside it at 760–1024px, and
  in the left gutter from 1025px. It uses live health device names and caches
  the last name in localStorage during startup. The backend prefers its default
  usable CUDA GPU, otherwise CPU; it does not rank multiple GPUs.
  `/api/health` exposes readiness and device details, never model identifiers.
  `RuntimeModelReadout.tsx` is retained but is not mounted by StudioShell.
- Brand: the mark (four waveform bars on a rounded tile, `--bg-base`/`--accent-2`)
  is generated by `scripts/build/build_brand.py` (favicons, touch icons, landing
  logo, `desktop/assets/icon.ico`; verify with `--check`). `BrandMark.tsx` renders it
  in the Studio header's left gutter, absolutely positioned so the centred
  `ParticleText` wordmark and the skeleton layout do not move. An inline copy
  also lives in the landing page; edit it together with the generator.
- `boneyard-js` supplies generated, source-controlled loading layouts in
  `apps/studio/src/skeletons/generated/`. Keep the Studio shell and static card
  controls rendered during model startup; `cloned-voices` covers only voice
  rows while their API data loads, `script-language` reserves the language
  control with a disabled placeholder during model startup and a skeleton
  while options load afterward, and `voiceover-history` covers uncached history
  or initial queue data. Keep API-loading placeholders in these generated
  skeletons; do not use Boneyard's Suspense wrapper because history uses
  ordinary React Query.
- `engine/qwen/` is the vendored CUDA-graph TTS wrapper. The backend supports a
  slow CPU fallback; Studio generation stays disabled unless health confirms
  the model is loaded on CUDA.
  `scripts/benchmarks/voice_generation.md` documents isolated offline profiling.
  `HOMEGROWN_STORAGE_DIR` can redirect source or packaged runtime storage;
  benchmark artifacts belong under ignored `.tmp/voice-speed/`.
  Voice-clone waveform streaming skips discarded reference-only vocoder blocks
  while preserving the original block alignment/context and PCM slicing; see
  `docs/waveform-decoding-results.md`. The full reference still conditions codec
  prediction. Keep inference timing instrumentation in benchmark scripts.
- There is one fixed local user (`local-user`), no accounts, and no workspaces.
  Ordinary API actions, including individual voice and voiceover deletion, do
  not require authentication. Permanent bulk deletion is additionally gated by
  `HOMEGROWN_ADMIN_PASSWORD`; this is not account authentication or user
  isolation. Bind only to trusted networks.

## History and cache contract

- `GET /api/history` is newest-first, accepts `limit`/`offset`, and clamps a
  page to `HISTORY_PAGE_MAX` (100). It filters by preset, date, duration, and
  canonical `q` voice-name search before pagination. Legacy built-in entries
  include a derived marker so Voiceovers filters omit them without rewriting
  historical records.
- `GET /api/presets` is newest-first and accepts optional `limit`, `offset`,
  and case-insensitive voice-name `q` search. It always returns an object with
  `presets` and `total`; `total` is the number of matching cloned voices before
  slicing. Each preset also includes `completed_voiceovers`, the aggregate
  number of successfully completed persisted history records for that voice,
  independent of history filters and pages. Generation completion and history
  deletion invalidate voice queries so these counts refresh. Requests without
  pagination parameters retain the full-list response
  behavior. The requested page size is clamped to 1–100 and offsets below zero
  become zero.
- `apps/studio/src/features/history/historyQuery.ts` owns history query keys, normalization, cache
  policy, persistence, and cache clearing. Keys are scoped to `local-user`.
- TanStack Query retains query data for 20 minutes in memory and treats it as
  stale after one minute. Its 24-hour localStorage persistence includes history,
  voice-list pages, and model-language options. Voice persistence projects only
  row/action fields; reference transcripts and storage paths are blanked. Queue
  snapshots, health/readiness, composer drafts, uploads, and generated audio are not in
  this API cache. Queue state remains in the in-memory query cache.
- `HistoryList` requests the active server page and prefetches one next page
  after a successful online response. It keeps previous data visible during a
  transition. Automated fetching is skipped offline; cached data remains
  available.
- Browser-local voiceover display names (`historyFileNames`) are not server
  data. Canonical searches cover all history; custom-name matches can narrow
  only loaded/cached pages. Voice preset names are server-side and are stamped
  into a history entry at generation time.
- A completed job invalidates history. Individual voice and history deletion require the
  shared Cancel/Delete confirmation modal, then defer the server DELETE for the
  seven-second Undo toast. History is optimistically
  removed when the request runs, rolls back on failure, and invalidates on
  success. Unmounting cancels pending client-side deletes. Requeue/reuse does
  not mutate history.
- The initial history skeleton is shown only when `isLoading` has no query
  data. Placeholder/cached history remains visible during refetches.

Both completed voiceovers and cloned voices expose Details in their three-dot
menus with an Info icon, using the shared RecordDetailsModal. Both details
panels share a 460px width and 520px height, constrained to the viewport, with
scrolling content. Script previews show at most 100 characters followed by an
ellipsis when truncated. Voiceovers show persisted generation
time; new clones persist server processing time as cloning_s (upload read,
validation, trimming and transcription, excluding network upload and browser
queue wait). Older voices show Not recorded. Voice cache projections retain
cloning_s without retaining private reference transcripts or storage paths.

## UI and queue contract

- The Script editor keeps an overflow-visible, rounded card frame. Its visible
  border is a final non-interactive overlay child, painted above the opaque
  footer; keep that element after the textarea and footer so every corner
  remains continuous when focused. The editor height uses
  `clamp(300px, 39svh, 400px)`; keep the input grid row flexible so the footer
  stays visible. The textarea receives initial focus. `useTypeToScript` routes
  eligible printable keys to it from non-editable Studio surfaces, but never
  intercepts searches, other editable controls, modifier shortcuts, composition
  input, menus, or dialogs.
- The Script editor's top-right **Paste from clipboard** control reads clipboard
  text, replaces the focused textarea selection or appends when it is not
  focused, and clips insertion to the remaining `MAX_SCRIPT_CHARS` capacity.
  Preserve caret placement. Clicking it invokes the browser clipboard API so
  the browser can request permission. Unavailable or denied access produces a
  toast with browser-permission and Ctrl+V guidance. The clear icon button below
  it is disabled for an empty script and clears the entire script otherwise.
  Undo and Redo controls sit above the word/character count in that same right
  rail. They track typing, paste, clear, and parent-driven text replacements,
  group rapid character edits, retain up to 100 steps, and restore the caret
  selection. Ctrl/Cmd+Z undoes; Ctrl/Cmd+Shift+Z or Ctrl/Cmd+Y redoes while the
  textarea is focused. Each control is disabled when its history is empty.
- The Script editor footer's script-language selector uses the shared
  Base UI menu-backed dropdown, populated from `GET /api/languages` (the loaded
  checkpoint's own `codec_language_id`, read once when the model reports
  ready). Its unselected option is **Select language**; an empty list hides the
  control except during model startup, when the disabled placeholder stays
  visible with the tooltip **Available when the voice model is ready.**
  Selection dropdowns must provide a field-specific `Select {label}`
  placeholder/default option. Keep meaningful, persisted settings (such as
  page size or System theme) selected instead of replacing them with prompts.
  Generation requires a non-empty script,
  an available voice, an explicitly selected script language, and a ready
  model. The composer language choice stays in memory and does not reset when the
  voice changes. Each generated job and history entry retains its selected
  language alongside its voice and transcript. Queue metadata exposes that
  language too. Reuse restores all three fields; Undo restores the previous
  composer snapshot. Legacy entries without a supported language require a
  fresh selection. `POST /api/generate` validates `language` against the
  same table and returns 400 otherwise, so an unsupported value is a refused
  request rather than a failed job.
- `ClonedVoicesSection.tsx` is the persistent voice-management card. It owns
  paged server-side voice search, selection, rename, preview, download, delete,
  pagination, and Clone voice. Only cloned voices appear in pages and the
  total count. Rows show successfully completed voiceover counts; a pulsing dot
  precedes the count while that voice is generating. Preserve the server count
  when reconciling page results with StudioShell's live preset objects. Voice
  page sizes are 50, 80, and 100 (default 50), stored separately from
  Voiceovers. Keep StudioShell's full-list request for generation and
  Voiceovers filters. Ignore stale page responses, reconcile returned records
  with current voices, and clamp the page when results shrink. Search and page
  size changes return to page one. Keep the empty-collection and no-match states
  distinct.
  File drops clone only when dropped on this card; the rest of Studio only
  suppresses the browser's default file-open behavior.
  Clone voice stays disabled until `wakeBackend` observes `model_loaded: true`.
  Generate additionally stays disabled until health confirms the model is
  loaded on a CUDA device; a CPU fallback does not enable generation.
  During startup the Clone voice control and voice selection rows are disabled
  with the tooltip `Available when the voice model is ready.` Generate retains
  its model-loading tooltip. The API
  may select CPU when no usable GPU exists;
  that fallback is ready only after its model initialization completes.
  During startup, render the real header, shell, and static controls
  immediately. Use generated skeletons for API-backed voice rows, language
  options, and uncached history or initial queue rows.
- Voice uploads keep the Clone voice label and Upload icon unchanged, and the
  action stays available while cloning. File selection and card drops accept
  multiple audio files and append them to a browser-local FIFO. Only one clone
  request runs at a time; selecting more files never interrupts that request.
- Each queued file has a persistent toast saying **Your uploaded voice is
  waiting to be cloned.** with its filename and an animated dashed `StatusMark`.
  When its turn starts, update that same toast to **Your uploaded voice is
  getting cloned.** with the amber spinner. On success, update it to **Your
  voice has been cloned.** with the animated green tick and dismiss after one
  second. Start the next file as soon as the request settles, without waiting
  for the success toast to expire. Errors identify the file and do not block
  subsequent uploads. Waiting animation respects reduced motion.
- Cloning cannot start before model readiness. Existing waiting files pause if
  readiness is lost and resume when it returns. Unmounting drops pending files
  and dismisses their toasts; an already submitted server request may finish.
  The upload queue is not persisted across page reloads.
- Backend startup failures are reported through a fixed, pulsing warning button
  at the lower-left of Studio; its modal shows the relevant message and Retry
  action when available. Do not put a failure banner above the Script editor.
  Failed background history refreshes keep cached rows and do not add an
  inline warning above the voiceovers list.
- `MascotPicker` is fixed to the viewport rather than participating in the
  composer or Voiceovers layout. Before a completed drag it follows the
  Voiceovers lower-left corner on wide screens and the viewport lower-left on
  narrow screens; after drag it retains only a clamped in-memory position.
  The mascot artwork is the drag surface. Mark only the side navigation
  controls with `data-mascot-navigation` and only the corner resize grip with
  `data-mascot-resize`, so their clicks cycle or resize without beginning a
  drag. The wrapper takes pointer capture lazily — only once movement passes
  the drag threshold — because capturing on pointerdown retargets the pointerup
  and the mascot's own button never receives the click that plays its reaction.
  A finished drag swallows exactly one trailing click on the artwork, never a
  navigation or resize click. The resize grip is keyboard-operable and bounded
  to 56–176px, defaulting to 80px below 640px and 112px at or above it; like
  the dragged position, the chosen size is in-memory only and is never
  persisted.
- `useOnboardingTour` keeps a static target sequence: header controls, voice
  controls, Script editor, Generate, Voiceovers, then search/filters. Its copy
  covers theme and mascot settings, bulk deletion, voice selection and batch
  cloning, script/language entry, generation queue behavior, playback, reuse,
  search, and filters. Do not add mascot, queue-row, error, or other conditional
  targets; the automatic model-ready tour must work on an empty Studio.
- The header Settings dialog is the only settings surface. It contains the
  theme picker and the **Pet animal** switch; hiding the mascot must not alter
  mascot assets, catalog generation, or generation state. The mascot switch is
  stored as `homegrown-mascot-enabled` in localStorage and defaults to visible
  when storage is unavailable or unset. Selecting a theme must not hide or
  remove any theme option or change their order. The resolved active theme may
  differ from the stored **System** choice.
- Settings also contains **Danger Zone** actions to permanently delete all
  generated voiceovers or all uploaded voices after confirmation, without Undo.
  The second confirmation requires the locally configured
  `HOMEGROWN_ADMIN_PASSWORD` from `services/voice-api/.env`; an unset password
  makes bulk deletion unavailable. Never put the secret in source control or
  user-facing documentation.
  Bulk operations cover all pages, preserve legacy built-in records and shared media,
  and refuse active generation; cloned-voice deletion also refuses active
  cloning and the browser's waiting clone queue. Media cleanup failures are
  reported separately from successful record deletion. Keyboard focus styles
  use the `--line-focus` token where provided. The Script editor textarea has no
  active outline, and focusing it does not change the editor frame border.
- Settings Backup downloads a password-protected ZIP of persisted application
  data and can restore one only after strong confirmation. Restore validates the
  entire archive, creates a pre-restore backup, refuses active generation or
  cloning, and never restores browser-local preferences, query cache, `.env`, or
  unrelated storage files.
- The mascot catalog is generated from top-level numbered pairs in
  `apps/studio/public/mascots/`: `<id>a.webp` is directions and `<id>b.webp`
  is reactions. Do not hand-edit `src/features/mascots/generated/mascotCatalog.ts`; add a pair,
  run a normal Studio command, and commit the assets with its regenerated
  catalog. Mascot 2 (the Cat sheets) is the default when it exists.
- Generate is a compact right-aligned action in the Script editor footer; the
  language selector is left-aligned. The selected voice is highlighted only in
  the voices card; the textarea has no voice header. Generate's tooltip exposes the Ctrl/Cmd+Enter
  shortcut when ready and the model-loading explanation while startup blocks
  it. Keep `.generate-action-auxiliary` visually stable and do not reintroduce
  shortcut or prerequisite copy beside the action.
- Completed rows are paginated with persisted page-size choices: 10, 25, 50,
  or 100. The fixed pager shows all pages through four; thereafter it shows a
  sliding window of five numbered buttons, always including the current page.
  Default display numbers must account for the server page offset.
- Live queued/running/failed rows come from `GenerationActivityContext`; do not
  fold them into completed-history cache data.
- Individual voice/history deletes are deferred behind a seven-second Undo toast; unmount
  cancels a pending delete. The toast uses the shared amber `StatusMark` ring
  to show the remaining Undo time. At the deadline, remove Undo and show the
  spinner until the request finishes; on success, animate a green check and
  dismiss after one second. Toast hover must not pause the deletion deadline.
  Queue cancellation is different:
  after the user confirms it, send it immediately and do not show an Undo timer
  toast. Keep this distinction in sync across the UI and API.
  A running job checks for cancellation between streamed audio pieces (about
  one second), so it may stop partway through a script chunk.
- The Voiceovers header contains search and a compact filter popover. Its footer
  contains pagination and the total history count, vertically centered. Do not
  restore batch selection or selection-action layout shifts.
  Filter selections apply to history immediately while the filter popover stays
  open; the Clear action and active count update without dismissing it. Only a
  click outside the filter popover or Escape closes it. The nested Base UI
  option menus are portaled; their pointer events must not be mistaken for
  outside clicks. Custom date and duration filters stay open through their
  explicit Apply action.
- Dropdown selectors, the theme menu, and voiceover action menus use
  `@base-ui/react/menu` through the shared `Dropdown.tsx` wrapper. Selection
  dropdowns share their raised surface, border, type, focus, and hover style
  through `.dropdown-select-trigger`; quick-filter triggers are shorter and
  use smaller text. The language and quick-filter option windows share the
  `standard-options-popup` style and 144px width (bounded by the viewport).
  Tooltips use the shared Base UI tooltip wrapper. Interface glyphs come from
  `lucide-react`. The animated status ring and undo countdown ring are bespoke
  visuals, not icon glyphs.
- A voiceover display name is local-only; a voice preset rename uses
  `PATCH /api/presets/{id}`. Do not merge these stores.
  Voiceover names, like voice preset names, stay read-only until their pencil
  button is clicked; clicking the name itself must not enter edit mode.
- Completed voiceover rows use a fixed-width editable name, a truncated script
  preview, and the timestamp in place of the voice name. The transport has a
  seekable progress bar; download and the overflow menu follow. Clicking the
  script preview reuses its transcript; the completed-row menu contains Details and Delete.
  Generating and queued rows reuse their script from the preview and have no
  overflow menu. Live rows share the compact name/script layout but expose
  queue/progress controls instead of completed download and overflow actions.

## Deployment and safety

- Local development and the Windows self-extracting build are supported.
- The app has no accounts or general API authentication. Ordinary API actions,
  including individual deletes, are unauthenticated; permanent bulk deletion
  requires `HOMEGROWN_ADMIN_PASSWORD`. Bind only to trusted networks.
- Never commit `.env`, model files, generated audio, or local storage data.
- The marketing page (`apps/marketing/`) is separate from the app and fully static.
  Its Contact section lists WhatsApp and email links; there is no form, backend or
  checkout/download link. Keep those two contact details in agreement with the README.

## Documentation

Keep `README.md`, `docs/workflow.md`, and this file in agreement with source.
`docs/archive/` is archived context, not current operational guidance.
`docs/reports/codegraph.md` is a dated graph snapshot, not a current index.
The `brag-output*/` plans, briefs and composition instructions describe
recorded video-production artifacts, not the current app UI or supported
development workflow. Preserve those artifacts as historical context.
After a skeleton fixture or app-shell layout change, regenerate the bones at
375, 768, 1025, and 1280px with `npm run bones:build`; do not hand-edit the
generated JSON or registry.
